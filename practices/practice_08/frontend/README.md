# AlgoPlace — Frontend (Практика 8: AI-Assisted Frontend)

Современный клиент платформы решения алгоритмических задач **AlgoPlace**, спроектированный и реализованный с использованием AI-инструментов, дизайн-системы **shadcn/ui** и сквозных клиентских тестов.

---

## 🚀 Команды проекта

```bash
# Установка зависимостей
npm install

# Запуск в режиме разработки (dev server на http://localhost:5173)
npm run dev

# Запуск всех клиентских тестов (Vitest + React Testing Library)
npm test

# Сборка проекта для продакшена (TypeScript + Vite)
npm run build
```

## 🎨 Дизайн-система и библиотека компонентов

- **Библиотека:** **shadcn/ui + Tailwind CSS** (на базе переиспользуемых примитивов Radix / Tailwind tokens).
- **Расположение компонентов:** `src/components/ui/`
  - `button.tsx` — кнопка со стилями variants (`default`, `primary`, `destructive`, `outline`, `ghost`, `link`, `sizes`, `focus-visible:ring-2`).
  - `badge.tsx` — бейджи сложностей (`easy`, `medium`, `hard`) и статусов (`success`, `destructive`).
  - `card.tsx` — карточки условий, примеров, тест-кейсов и панелей.
  - `dialog.tsx` — модальное окно с `role="dialog"` и доступностью по клавише Escape.
  - `alert.tsx` — баннеры ошибок, предупреждений и валидации (`Alert`, `AlertTitle`, `AlertDescription`).
  - `spinner.tsx` — анимированный индикатор загрузки (`role="status"`).
  - `input.tsx` — стилизованные инпуты с подсветкой фокуса.
- **Единое оформление (Theme Tokens):**
  Задано в `src/index.css` через CSS-переменные (`--background: #0a0a0b`, `--card: #111113`, `--primary: #10b981`, `--destructive: #f43f5e`, `--ring: #6366f1`, `--radius: 0.5rem`).

## 📐 Макет и прототип (AI-Mockup)

- **Интерактивный макет:** расположен в [`docs/mockup/index.html`](../docs/mockup/index.html).
- **Как открыть:**
  ```bash
  firefox docs/mockup/index.html
  # или xdg-open docs/mockup/index.html
  ```
- **Все 5 состояний интерфейса:**
  1. `Initial` — условие задачи, заготовки кода на C++/Python, примеры, начальный тест-кейс.
  2. `Loading` — блокировка кнопок (`disabled`), индикатор `Evaluating...`, спиннер.
  3. `Accepted (Success)` — бейдж `Accepted`, метрики (Runtime, Memory), окно «Task Solved!».
  4. `Wrong Answer (Error)` — статус ошибки, алерт с описанием несовпадения вывода, кнопка `Retry Submission`, подсветка упавшего теста.
  5. `Empty Data` — заглушка до запуска решений.

## 👤 Пользовательский сценарий (User Flow)

1. **Вход и выбор задачи:** пользователь открывает каталог задач (фильтрация по сложности, поиск с дебаунсом) и выбирает задачу (например, *1. Two Sum*).
2. **Написание кода:** в рабочей области доступен редактор кода (Monaco Editor) с переключением языков (C++, Python 3.12, JavaScript) и кнопкой сброса к шаблону.
3. **Отправка на проверку (Submit):**
   - **Валидация:** если код пустой, запрос не уходит, а выводится понятный `Validation Error` алерт.
   - **Защита от double-submit:** на время запроса кнопки `Run` и `Submit` блокируются (`disabled`), повторный клик или Enter не дублируют вызов API.
   - **Загрузка:** отображается анимация загрузки «Compiling and judging against test suite...».
4. **Результат:**
   - При успехе: зеленый бейдж `Accepted`, время работы и память, модальное окно с переходом к следующей задаче.
   - При ошибке: отображение упавших тест-кейсов с разницей между `Expected` и `Actual`, кнопка повторной отправки.

## ♿ Доступность (a11y) и UX

- Все поля ввода и выпадающие списки снабжены `<label>` или `aria-label`.
- Все интерактивные кнопки имеют видимый индикатор фокуса (`focus-visible:ring-2 focus-visible:ring-indigo-500`).
- Полная навигация сценария доступна с клавиатуры (клавиши `Tab`, `Enter`, `Escape`).
- Адаптивная верстка: читаемость на мобильных и узких экранах (grid 1 колонка на экранах `< 1024px`, 2 колонки на десктопе).

## 🤖 Отчет об использовании AI

1. **Инструменты:** AI-ассистент (Antigravity / Claude), генерация прототипа на HTML5/CSS3 с токенами shadcn/ui.
2. **Примеры запросов (промптов):**
   - *«Спроектируй макет рабочей области задачи Two Sum в стилистике shadcn/ui: слева условие и примеры, справа редактор и консоль. Сформируй 5 состояний: Initial, Loading, Accepted, Wrong Answer, Empty»*.
   - *«Сгенерируй набор клиентских тестов на Vitest и React Testing Library для проверки защиты от double-submit при отправке решения, валидации пустого кода и мокирования состояний сервера»*.
3. **Вклад человека и исправления после AI:**
   - Синхронизированы типы TypeScript (`Problem`, `SubmissionResult`, `SupportedLanguage`) с бэкендом.
   - Защита от double-submit усилена как на уровне атрибута `disabled` кнопки, так и на уровне обработчика функции (`if (isSubmitting) return;`).
   - Настроено безопасное мокирование сетевых запросов и относительных URL в окружении JSDOM.
